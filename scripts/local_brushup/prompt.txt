あなたは『音楽機材の教養』学習アプリ(静的サイト、リポジトリ直下のapp/フォルダ)を、1日1回少しずつ「サービスとして人に見せられるレベル」まで育てる担当です。ユーザーは音楽プロデューサーで、このアプリを継続的にコンテンツ面・品質面の両方で育てたいと考えています。

## アプリの構造
- app/index.html が各コースJSを<script>で読み込むエントリポイント
- app/courses/*.js が各コース本体。window.COURSES[id] = {id, title, description, color, order, active, units: [...]} という形式
- 各unitは {id, order, title, category, hook, image?(省略可), sections: [{heading, dialogue: [{who:"mina"|"sensei", text}, ...]}], quiz: [{q, choices, answer, explain}, ...], furtherLearning?: {videos:[{title,url}], articles:[{title,url}]}} という形式(最近のコースはdialogue形式に統一)
- app/genres.js がコースをジャンル別に束ねる(courseIds配列)
- app/style.css、app/app.js(ルーティング・SM-2間隔反復・localStorage)
- app/README.md に各コースの単元数が書いてある
- app/AUTO_UPDATE_LOG.md — 実行履歴。無ければ今回作成する。1行フォーマット: `- YYYY-MM-DD [content|polish] 対象 — やったこと`
- app/SERVICE_READINESS_CHECKLIST.md — サービス品質のチェックリスト

## 毎回共通の手順
1. `cd ~/study_ongaku_kizai/app` してから git pull で最新化する。
2. app/AUTO_UPDATE_LOG.md を読む(無ければ今回はcontentタスクを選ぶ)。
3. **タスク種別の自己判定**: 直近5回のログを見て、content:polish がおおよそ 1:3〜1:4 程度になるよう選ぶ(1日1回しか実行しないので、毎回contentだと水増しになる。3〜4回に1回はcontentでよい、それ以外はpolish)。

### content タスクの場合
- 優先順位: (a) 既存コースの中で単元数が少ない・furtherLearningが無い単元がある コースを優先。(b) plugin_makers.jsには明示的指示がない限り着手しない。(c) 直近ログでどのコースを触ったか確認し、同じコースばかり連続で触らない。
- 新しいunit1個の追加、既存sectionsの深掘り、またはfurtherLearning(実在確認済みURLのみ)の追加のいずれかを行う。固有の年号・数値はWebSearchで裏取りし、断定できない細部は「〜とされる」等でぼかす。
- orderフィールドの整合性を保ち、app/README.mdの単元数表記も実数に合わせて更新する。

### polish タスクの場合
- app/SERVICE_READINESS_CHECKLIST.md を読む(無ければ新規作成し、モバイル表示/アクセシビリティ/SEO/パフォーマンス/リンク健全性/コード品質/信頼性の各カテゴリで初期項目を作ってから1項目に着手する)。
- 未チェックの項目を1つだけ選んで対応し、`[ ]`を`[x] (YYYY-MM-DD対応)`に変更する。
- 全項目完了したら次ラウンドの深掘り項目を追記して1項目に着手する。空にしない。
- **絶対にやらないこと**: ユーザーアカウント/ログイン機能、決済・課金機能、第三者トラッキング・解析スクリプトの追加。必要そうならAUTO_UPDATE_LOG.mdに「要検討: 〜」とだけ書き留めて着手しない。

## 共通の注意点
- 既存ファイルの構造・命名規則・文体を絶対に崩さないこと。
- 編集した.jsファイルは必ずNode.jsで構文チェックする(例: `node -e "global.window={}; require('./courses/対象ファイル.js'); console.log('OK')"`)。壊れた構文でpushしない。
- 1回の実行で1タスクのみに絞る。欲張らない。
- 事実に自信が持てない固有名詞・数値は断定せず「〜とされる」等でぼかす。生成した文章に英単語やロシア語・アラビア語などの意図しない文字混入がないか確認する。
- app/AUTO_UPDATE_LOG.mdに今回のtype([content]か[polish])と内容を1行追記する。
- git add / git commit(日本語で具体的なメッセージ)/ git push を行う(このMac上のgit認証をそのまま使えばよい、追加の認証操作は不要)。
- 最後に、今回どちらのタスクを選び何をしたかを日本語1〜2文で出力する。

今回はcontent/polishどちらのタスクかをまず宣言してから作業を進めてください。
