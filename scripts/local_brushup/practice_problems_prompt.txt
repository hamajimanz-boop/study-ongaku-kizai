あなたは『音楽機材の教養』学習アプリの「実践問題編」を担当します。既存の2コースを手本に、今回の実行で**新しいunitを合計10個以上**追加してください。

## 対象コース(app/courses/ 配下)
1. `gear_patch_practice.js` (kind:"patch") — 実在の機材モデル名で構成した配線パズル。scenario(状況説明)/equipment(機材とport定義)/cablePalette/correctConnections/explain を持つ。既存9単元をよく読んで、同じ密度・同じJSON構造・同じ文体(「〜を配線しよう」というhook、実務的なexplain)で新しいunitを作る。
2. `money_case_studies.js` (kind:"case") — 簿記/FP/音楽ビジネスの数字を使った計算問題。scenario(状況、配列)/inputs(choice/number形式の設問配列、それぞれanswer/explain付き)/explain(配列)を持つ。既存6単元をよく読んで、同じ構造・同じ文体で新しいunitを作る。

## 進め方
1. `cd ~/study_ongaku_kizai/app` してから `git pull` で最新化する(他のセッションが同時に作業していることがあるため、pullしてから作業を始めることが特に重要)。
2. 両ファイルを読み、既存unitのidと内容を把握する(重複するシナリオを作らないため)。
3. 新しいunitのアイデアを最低10個考える。配分の目安: gear_patch_practice(配線パズル)に6〜7個、money_case_studies(ケーススタディ)に3〜4個。ただし既存内容と被らないよう、無理のない範囲で調整してよい。
   - patchのアイデア例(あくまで例、実際は自分で考える): MIDIキーボード+シンセの配線、ライブPA(ミキサー→パワーアンプ→スピーカー)、配信/ポッドキャスト用マルチマイク配線、外部エフェクター(リバーブユニット)のセンド/リターン配線、ドラム収録の複数マイキング、Bluetoothではなく有線での楽器⇄オーディオI/F接続の使い分け、S/PDIF・AES/EBUなどデジタル伝送、ラックマウント機材のパッチベイ運用、配信用のオーディオミキサー(ライブ配信でPCとハードミキサーを繋ぐ)など
   - case studyのアイデア例: 印税分配のさらに別パターン(共作曲の按分計算)、消費税の簡易課税制度、青色申告特別控除の計算、開業費の償却、経費按分(自宅兼スタジオの家事按分)、小規模企業共済の掛金と節税額、ライブ物販の原価計算、クラウドファンディングの税務処理など
4. 1個ずつ、実在の機材名・法制度・数値をWebSearchで裏取りしながら丁寧に作成する(適当な数値を捏造しない。数値が不確かな制度は最新情報を検索して確認する)。
5. 1個作るごとに、対象ファイルにunitを追記し(orderフィールドの整合性を保つ)、`node -e "global.window={}; require('./courses/対象ファイル.js'); console.log('OK')"`で構文チェックする。
6. 構文チェックが通ったら、その1個分だけをgit add / git commit(日本語で具体的なメッセージ、例:「配線パズル: MIDIキーボード接続の単元を追加」)/ git pull --rebase / git push する。1個ごとに小さくpushすることで、途中で止まっても成果が残るようにする。
7. これを繰り返し、合計10個以上のunit追加が完了するまで続ける(1回の実行で欲張りすぎて15個を超えたら、そこで区切ってよい)。
8. 最後に、今回追加したunit数とタイトル一覧を日本語で出力する。

## 注意点
- 既存ファイルのJSON構造・命名規則・文体(patchのhook文体、case studyのexplain文体)を絶対に崩さない。
- 生成した文章に英単語やロシア語・アラビア語など意図しない文字混入がないか確認する。
- 事実に自信が持てない固有名詞・数値・法制度の細部は、WebSearchで裏取りするか、断定せず「〜とされる」等でぼかす。特にcase studyの税制・保険料等は年度で変わるため、既存unitと同様「実際の申告時は最新情報を確認すること」等の注記を添える。
- pushで衝突(conflict)が起きた場合は、`git pull --rebase`で解消してから再度pushする。解消できない深刻な衝突が起きた場合は、無理に解決しようとせず、状況をそのまま最後の報告に書いて終了する。

まず対象ファイルの現状を確認してから、追加するunitの一覧(タイトルだけ)を最初に宣言してから作業を進めてください。
